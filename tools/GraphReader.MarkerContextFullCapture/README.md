# Marker context full train-raster capture

This separate diagnostic is pinned to the nonapproved, synthetic-only v5 full train raster corpus: 64 sources from `marker-context-train-corpus-v5-full`. The tool binds the corpus binding, completion receipt, identity manifest, raster manifest, every source ID and PNG hash, the reviewed two-source smoke report, the reviewed marker/OCR model and license binding, and this tool's source/runtime. It never resolves the corpus truth file or any annotation.

The processing path is the same production importer, raster decoder, candidate OCR adapter, axis geometry adapter, V27 marker-center adapter, marker-input builder, and sampler as the reviewed two-source smoke tool. The unchanged center-binding validator verifies the detector, recognizer, center model, manifests, licenses, shared implementation sources, and managed/native runtime. Before OCR adapter creation, the tool writes an initialization-probe start receipt because adapter creation may run zero-image probes; it records completion or an initialization-failure receipt separately from per-corpus panel inference start receipts. The marker-classifier model is absent and is never loaded. This is data capture only, not classifier inference, optimization, training, accuracy evaluation, or training approval.

The capture processes one source and one production workflow store at a time, writes each panel event immediately, and retains only source/panel summaries between sources. Preflight rejects more or fewer than 64 rows, duplicate IDs/seeds/image hashes, non-1200×350 inputs, missing/extra raster files, hash changes, reparse-point paths, dev/private/sealed scope, or any approval flag. Sources are locked while the descriptor is active. Individual panel JSON serialization is capped at 64 MiB and total event output at 2 GiB; each source PNG is at most 1 MiB and each source has at most eight panels. The event cap runs during JSON serialization after proposal, crop, and sampler-view arrays have already been allocated, so it limits persisted event size, not peak memory. Processing is serial to limit cross-source retention, but no hard process-memory bound is claimed. A 30-minute cancellation token is cooperative and cannot guarantee a hard deadline for noncooperative native calls. If a panel exceeds its event bound, that panel is recorded failed and later panels/sources continue. A process cancellation or fatal failure leaves a start/progress record and per-source ledger files but no final report. A final report distinguishes `source_accounting_complete` from `all_sources_succeeded`; a fully accounted run with any failures exits 3 and prints a failure status, never `CAPTURE_ALL_SOURCES_SUCCEEDED`.

The two smoke images are present in the 64-source full corpus at their authenticated image hashes. The full report compares those exact raster identities against the completed smoke report's source/panel/proposal/view counts. This is a plumbing consistency check only and makes no acceptance claim. The smoke run used 27 and 36 proposals, wrote about 2.82 and 2.89 MiB per panel, took 13.91 seconds including initialization, and peaked at 601,448,448 bytes for the whole process. A linear extrapolation is only a rough planning estimate. Runtime records whole-process elapsed time and cumulative process peak working set, including model loading and inference; per-source values are working-set snapshots, not source-local peaks. It labels the pre-capture current working set separately from the pre-capture process-lifetime peak.

No full-capture inference has been run by this tool. `--preflight` verifies all bindings and image bytes without constructing ONNX sessions. `--capture` requires a separate review receipt pinned to the exact descriptor, protocol, and assembly, with diagnostic model inference allowed and classifier/training approval explicitly false. The receipt must be independently reviewed before capture. The project remains synthetic-only and unapproved for production.

Build with project-local .NET caches and temporary paths:

```powershell
dotnet build tools\GraphReader.MarkerContextFullCapture\GraphReader.MarkerContextFullCapture.csproj --configuration Release --verbosity minimal -m:1 -p:NuGetAudit=false -p:UseSharedCompilation=false
```

`Prepare-FullCaptureBinding.ps1` creates a fresh v4 runtime bundle and descriptor after the build outputs match the reviewed parent runtime. Launch the copied assembly from `artifacts\goal22-runs\marker-context-bound-input-full-runtime-v4`; the bound executable directory is required so the shared validator sees the pinned files. Review the newly prepared descriptor before any capture. The fixed output directory must be fresh.
