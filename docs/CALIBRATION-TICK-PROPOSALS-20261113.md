# Reviewed calibration from measured ticks

## Product change

Continue the development reset after automatic device profiles, pushed in
`9b08fd6a2ceb896259e9653e8e104fee51dc6c53`. A numeric label's center is not an
axis tick position. Assigning the largest label to the end of an axis can
silently change the scale. This batch pairs OCR labels with measured tick
pixels before proposing any calibration values.

The existing Rust worker now reports bounded X/Y tick positions in original
panel pixels. The managed reader accepts the older endpoint-only response too.
No frozen project, model or vision-result schema changes. A pure proposal
service requires unambiguous label/tick associations, monotonic sequences,
consistent linear fits, observed endpoint labels and an observed zero. Missing
or inconsistent evidence leaves the proposal incomplete with review reasons.
It does not extrapolate an endpoint, invent zero/session 1, or substitute a
label center for a measured tick.

The native UI gains a single Suggest calibration action through the existing
axis and OCR workers. Its values and anchors remain editable proposals. The
review confirmation remains mandatory; generation does not apply calibration,
save scientific values or export data. Original source bindings still guard
against stale results. Existing quick axis, label and manual controls remain.
