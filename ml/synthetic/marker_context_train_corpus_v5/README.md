# Marker-context train corpus V5

This is an unapproved full-producer and capture-plan foundation. The fixed plan covers 64 train seeds and all 16 design/connection/cue cells equally. A full corpus was rendered after review; no model training has occurred. This revision accepts only the full plan, uses its own binding, and requires independent review before execution. It binds the separately completed V3 smoke receipt, raster manifest and scene/image identity mapping, and requires both smoke cases to reproduce the same scene and image hashes within the full generation.

The producer replaces only parameter-free deterministic grayscale stages in the `none` family with explicit no-ops. All other degradation families/stages fail closed. Connected and missing-edge scenes must contain their expected positive control. In-plot overlays, including uncued cases, remain review-only and cannot become automatic negatives. Overlay visibility checks are source-pixel checks; wide-patch visibility, classifier-factory parity and negative-label admission are not established.

The worker-facing raster manifest contains image identity/dimensions and predeclared source IDs, with no cue or truth fields. A separate metadata file binds source ID, image SHA, catalog scene ID and revision-scoped case ID; truth remains in a separate sidecar. The generator compares train image/scene/source IDs against hash-bound dev metadata only, never dev rasters or truth. The same train seeds may occur in older diagnostics, so identity is the composite `(revision, case_id, scene_id, marker_id)` rather than a claim that nested marker IDs are globally fresh. Imported production panel IDs are not yet observed.

The Windows isolated launcher verifies source files and no-writer locks before project imports, runs one process, writes an incomplete/failure receipt when possible, and writes `COMPLETE.json` last. Failure accounting lists planned, attempted, per-case completed, failed and unattempted recipe IDs and counts; completed means rendered through per-case checks, not admitted or durable. If a post-build receipt cannot authenticate the identity metadata, accounting is explicitly unavailable rather than invented. Its receipt records elapsed time and peak working set for that Python process only; it excludes production inference and system-wide peak memory. The launcher and interpreter execute before their own source check, and installed packages/OS are not attested. Directory-race and external/historical independence limitations remain.
